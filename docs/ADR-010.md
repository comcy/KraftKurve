# ADR-010: Multi-Theme System via CSS Custom Properties

**Date**: 2026-06-07

## Context
The app launched with a single "Tactical" dark theme. Users may prefer a cleaner, more mainstream aesthetic for daily use. The team wants to add a "Minimalist Premium" look without maintaining two separate component codebases.

## Decision

**3 themes**: `tactical` (default), `minimal-dark`, `minimal-light`.

**Mechanism**: CSS custom properties on `:root.theme-{name}`. `ThemeService` in `shared-utils` applies the class to `document.documentElement`. An inline bootstrap script in `index.html` pre-applies the class before Angular initializes (no flash).

**Font strategy**: `--font-headline` and `--font-body` are CSS vars overridden per theme block. Angular Material M3's compiled typography (baked-in static CSS) is overridden for minimal themes via:
1. MDC CSS token custom properties (`--mdc-filled-text-field-input-text-font`, etc.)
2. Direct `!important` rules on Material component selectors inside `:root.theme-minimal-*`

**Icon stability**: `mat-icon` global rule adds `text-transform: none !important` and `font-weight: normal !important` to prevent parent button styles (`uppercase`, bold) from breaking Material Symbols ligature rendering.

**`AppTheme` type** exported from `shared-utils` for use anywhere that needs to reference theme names.

## Consequences
- **Pros**: Single stylesheet, no component duplication. Theme switch is instant (class swap). CSS vars inherit to all descendants automatically.
- **Cons**: Angular Material M3 compiled theme is always the tactical dark palette; minimal themes override it surgically via `!important` rules which is slightly fragile if Material updates internal class names.
- **Backward compat**: Old `'dark'`/`'light'` localStorage values migrate to `'tactical'`/`'minimal-light'` automatically.
