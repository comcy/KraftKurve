# ADR-006: Mobile Auth Integration & Admin Separation

**Status:** Accepted  
**Date:** 2026-05-25

## Context
The mobile app (`kraftkurve-mobile-app`) lacked integrated authentication, resulting in 401/403 API errors. Additionally, we needed to decide where administrative features (like generating invites) should reside to maintain a clean mobile user experience.

## Decision
1.  **Unified Authentication**: Integrate the existing `AuthInterceptor` and `AuthService` from `lib-auth-data-access` into the mobile app to ensure JWT tokens are automatically attached to all API requests.
2.  **Persistent Session**: Use `localStorage` to persist the JWT token, fulfilling the requirement that users stay logged in until an explicit logout action is performed.
3.  **Strict Admin Separation**: Administrative features (Invite generation, User management, Global exercise catalog) will remain exclusively in the Web Admin App. The mobile app is strictly for end-user functionality (Training, Nutrition, Progress). Even when an admin logs into the mobile app, they will only see the user-facing features.
4.  **Route Protection**: Secure all mobile-app routes with `authGuard` to ensure unauthenticated access is impossible.

## Consequences
- **Pros**: 
  - Reduced complexity and "noise" in the mobile app by omitting complex tables and admin forms.
  - Consistent security model across all project applications.
  - High performance by keeping the mobile bundle focused on tracking features.
- **Cons**: 
  - Admins must switch to a desktop/web browser UI to manage invites.
