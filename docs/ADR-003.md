# ADR-003: Normalized User Settings Storage

**Status:** Accepted
**Date:** 2026-05-24

## Context
User-specific nutrition settings (protein goal, presets) were previously stored within the `User` entity. This led to a monolithic data structure in `users.ndjson`.

## Decision
Move user-specific settings to a dedicated `nutrition-settings.ndjson` file. Use `userId` as a foreign key to link settings back to the user.

## Consequences
- **Pros**: Cleaner `User` entity, better data normalization, easier to extend settings without modifying the core user profile.
- **Cons**: Requires a join/lookup when fetching user data along with their settings.
