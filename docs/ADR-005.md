# ADR-005: UI Layering & Input Refinement

**Status:** Accepted  
**Date:** 2026-05-25

## Context
The "Tactical Logbook" design required high legibility and a sense of physical layering. Initial implementations faced issues with background grid movement and input fields looking too "web-standard" with browser-specific buttons.

## Decision
1.  **Stationary Background Grid**: Move the graph-paper grid to a `fixed` pseudo-element (`html::before`) with a low `z-index`. Keep the `body` and content background transparent, while setting opaque backgrounds for widgets and navigation bars.
2.  **Numeric Input Refinement**: Switch all numeric data-entry fields to `type="text"` with `attr.inputmode="numeric"` or `decimal`. Use CSS to hide default browser spinners.
3.  **Solid Surface Bars**: Enforce 100% opacity on header and navigation bars using `!important` and explicit surfaces to prevent scrolling content from being visible behind them.

## Consequences
- **Pros**: 
  - Stationary grid provides a consistent "desk" metaphor while scrolling.
  - Opaque bars ensure zero visual noise during navigation.
  - Clean inputs focus the user on raw data without distracting UI widgets.
  - Maintains full mobile keyboard functionality.
- **Cons**: 
  - Pseudo-element grid requires careful layering of all other components.
  - `inputmode` binding requires attribute binding (`attr.inputmode`) in Angular templates.
